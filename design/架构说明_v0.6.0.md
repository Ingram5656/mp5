# 架构说明 v0.6.0：MVP（Model–View–Presenter）

v0.6.0 沿用 v0.5.4 的三层结构，加入摇牙挑战关卡 B“兔子的气球”。下面第 0 节是 v0.6.0 的变化，其余各节为 v0.5.4 的原文（文件清单已按 v0.6.0 补充）。

## 0. v0.6.0 新增和改动

| 层 | 新文件 | 内容 |
|---|---|---|
| Model | `balloon_model.gd` | 气球关规则：等待 → 跟着加力线上升 → 保持 → 绑气球；太快漏气、超过上限爆掉、失误次数、计时；记录采样（含标准加力线、目标、阶段）和事件；日志行和评估数据 |
| Model | `evaluation_balloon.gd` | 气球关评分和 CSV 读取（`design/评估方法_v0.6.0.md`） |
| Model | `keyboard_ramp_source.gd` | 气球关的键盘输入：按住慢慢加力，松开键保持不变 |
| View | `balloon_view.gd` | 气球关画面：兔子、打气筒（把手随力下压）、软管、气球（大小随力矩）、虚线圈 / 目标刻度、保持进度弧、漏气 / 爆炸 / 绑气球 / 胜负动画、失误次数、气球槽、沙漏、实习生底部曲线条、结算面板 |
| Presenter | `balloon_presenter.gd` | 气球关的一局，`balloon_game.tscn` 的根节点脚本 |

改动：`round_log.open()` 可指定文件名前缀和列名；`achievement_db.record_round()` 对气球关只写历史记录，不计成就统计；`achievement_defs` 增加 `GAME_BALLOON`；报告视图、报告主持者、报告导出按局里的 `game` 区分两关；历史记录显示关卡名并用对应的评分模块重建报告；选择页“摇牙挑战”可选关卡 A / B；`app_presenter` 按所选关卡启动对应游戏。

分层检查（第 1 节的三条）在 v0.6.0 写入前重新做过，全部满足。模型测试增加到 17 项（新增 6 项气球关测试）。


从 v0.5.4 起，整个应用（连接页、入门测试、游戏选择、成就、历史记录、拔萝卜、评估报告）按 MVP 分成三层。功能、画面和规则与 v0.5.3 相同，只是代码重新分了家。

## 1. 三层各管什么

| 层 | 文件夹 | 负责 | 不允许 |
|---|---|---|---|
| **Model（模型）** | `scripts/models/` | 规则、数据、计算、读写文件：拔萝卜规则、入门测试的三把锁、评分、成就数据库、CSV 日志、报告导出、语言设置、模拟传感器 | 不创建任何界面节点，不引用 `views/` 和 `presenters/` |
| **View（视图）** | `scripts/views/` | 画界面、播动画、翻译文字；用户点了什么就发出信号 | 不知道游戏规则，不读写文件或数据库，不引用 `models/` 和 `presenters/` |
| **Presenter（主持者）** | `scripts/presenters/` | 拥有模型和视图：把模型的状态交给视图显示，把视图的信号交给模型处理，决定下一步做什么（换页、开局、结算、存档） | 不自己画界面 |

检查方法（每次改代码后都应该成立）：

- `views/` 里没有 `preload(".../models/...")` 或 `preload(".../presenters/...")`
- `models/` 里没有 `preload(".../views/...")` 或 `preload(".../presenters/...")`，也没有 `Label.new()`、`add_child()` 之类的界面代码
- `views/` 里没有 `FileAccess`、`DirAccess`、`ConfigFile`、`record_round`

v0.5.4 写入前已按以上三条逐一检查，全部满足。

## 3. 拔萝卜一帧里发生了什么

1. `carrot_presenter` 从输入源读一个力矩（键盘模拟或真实传感器）。
2. 调用 `rocking_model.step(delta, 力矩, 偏轴, 拔力)`，模型更新状态，并给出这一帧的事件（如 `hold_ok_R`、`rock_3`、`overload`、`win`）和局中成就（如 `rock_shh`）。
3. 主持者按事件调用视图：`show_progress()`、`show_rock()`、`show_overload()`、`show_offaxis()`、`play_win()`、`play_lose()`；局中成就写入数据库并弹窗。
4. 主持者把模型的显示状态（倾角、保持进度、是否接近上限、提示文字等）交给 `carrot_view.render()`。
5. 把模型生成的这一帧日志行写进 CSV。

## 4. 好处

- **规则可以单独测试。** `tests/run_tests.tscn` 按 F6 运行，不打开游戏画面就能检查 11 项规则（交替、同侧不算、用力过猛锁定、大师一次失误即断、计时、偏轴、局中成就、退出、记录格式、入门测试、评分），结果显示在屏幕和“输出”面板上。这些测试不读写数据库或任何文件。
- **接真实传感器只改输入源。** 把带 `read()` 的节点交给 `carrot_presenter.sensor`，规则和画面都不用动。
- **换画面不影响规则。** 例如以后给第二类游戏做新画面，可以照着 `carrot_view` 写一个新视图，配一个新的规则模型。

## 5. 与 v0.5.3 的细微差别

- CSV 日志第一列 `t_s` 改为从本局打开时开始计时；之前是从程序启动时开始。读日志时只用相对时间，所以评分和历史记录不受影响，旧日志也照常能读。
- 拔萝卜结束那一帧不再更新萝卜倾角（之前在同一帧先倾斜、后被结束动画摆正）。肉眼看不出区别。
- 入门测试的保持进度条改为 0–1 的比例显示；之前是 0–1 秒。保持时间都是 1 秒，所以显示完全一样。
