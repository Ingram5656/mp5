## 1. 为什么要改

v1.1 把界面当成一台校准过的测量仪器：瓷白底、细灰线、只有墨蓝灰和钢灰，颜色只在出状态时出现。那时候还没有游戏画面，这个方向是对的。

现在有了两个游戏，它们的画风很统一：

- 天空蓝背景、木栅栏、草地和翻过的泥土；
- 所有物体都有一圈**粗而均匀的可可色描边**（素材里大约是 `#6C3C0C`）；
- 大块平涂颜色，每个物体只有一块柔和的高光；
- 形状圆润、略带手绘的不规则感，例如结算面板是一块边缘起伏的木牌（`ui_result_panel.png`）；
- 角色是奶油色的兔子，主角是胡萝卜。

问题是，从游戏回到菜单就像换了一个软件：结算面板是木牌和橙色按钮，按“返回选择”后是冷白色的仪器界面，评估报告也是。v2.0 让菜单、测试和报告都进入同一片菜园。

## 2. 核心概念：界面是菜园里的东西

> 页面背景就是菜园，内容写在插进土里的木牌上。

| 界面里的东西 | 在菜园里是什么 | 用到的素材或做法 |
| --- | --- | --- |
| 页面背景 | 天空、栅栏、草地和泥土（与游戏同一张背景，不放兔子和萝卜） | `bg_sky` + `bg_fence` + `bg_soil_back` + `bg_soil_front` |
| 内容面板 | 下面有两根木桩、插在土里的大木牌 | `ui_result_panel.png` 做九宫格拉伸，木桩用代码画 |
| 应用名 | 左上角歪着挂的小木牌 | 代码画 |
| 游戏列表 | 三块路牌，选中的那块被拉出来 | 代码画 |
| 仪表 | 钉在木牌上的奶油色铭牌 | 代码画 |
| 评估报告 | 夹在木牌上的方格笔记纸 | 代码画 |
| 成就提示 | 用两根绳子吊下来的小木牌 | 代码画 |

**整个界面只在这一处大胆：木牌和描边。**其余部分（文字、间距、图表）保持安静，以便读数和报告仍然清楚。

## 3. 设计令牌

### 3.1 颜色

颜色分三组，各管各的事：**世界色**搭场景，**动作色**表示“可以按”，**状态色**表示“出事了 / 做到了”。

| 组 | 名称 | 色值 | 只用在 |
| --- | --- | --- | --- |
| 世界 | 天空蓝 Sky | `#5CC8F8` | 页面底色（背景图加载失败时的底色） |
| 世界 | 木牌 Plank | `#F7CF8A` | 木牌、路牌、挂牌 |
| 世界 | 木牌边 Plank edge | `#E3A24A` | 木牌下沿的厚度、木桩 |
| 世界 | 奶油纸 Paper | `#FFF4DF` | 铭牌、报告纸、次要按钮、标签 |
| 世界 | 可可墨 Ink | `#5E3410` | **所有描边**、正文、读数、指针杆、选中的标签底色 |
| 世界 | 干土 Soil | `#9A6A44` | 次要文字、刻度、分项分数条 |
| 动作 | 胡萝卜 Carrot | `#FF7F1F`（下沿 `#C95A0C`） | 每页**只有一个**主按钮（开始、再来一次、保存），以及仪表指针头、选中路牌的下沿 |
| 状态 | 叶绿 Leaf | `#5FB52A`（未进入时的嫩叶 `#B9E38F`） | 在目标区内、已解锁、过关评级章、“绑好”标记 |
| 状态 | 向日葵 Sun | `#FFC531` | 连接中、等待、接近上限 |
| 状态 | 番茄 Tomato | `#E8442E` | 失误、过载、断线、上限线、未过关的 F |

与 v1.1 的对应关系：瓷白 → 天空 + 木牌；墨蓝灰 → 可可墨；钢灰 → 干土；目标青绿 → 叶绿；琥珀 → 向日葵；警示红 → 番茄。

**规则：**

1. 绿、黄、红仍然**只表示状态**，这一条从 v1.1 保留下来。
2. 橙色是“动作色”，一页只有一个橙色实心按钮。
3. 蓝、木色、奶油、可可、干土是场景色，可以大面积使用。
4. 图表里“标准曲线”用深天蓝 `#2E8FC4` 虚线：它既不是状态也不是动作，用天空色系与玩家曲线（可可墨实线）区分。

对比度（WCAG 计算）：可可墨在奶油纸上 9.8:1，在木牌上 7.2:1；干土在奶油纸上 4.3:1，只用于 13 号以上的次要文字（略低于正文 4.5:1 的标准，所以不用干土写正文）。白字在胡萝卜橙上只有 2.5:1，低于大字号的 3:1；可可墨字在胡萝卜橙上是 4.2:1。所以**主按钮建议用可可墨字**，样张里的白字只是为了对比，待你确认（第 8 节）。

### 3.2 描边与形状

| 元素 | 描边（1920 宽设计稿 / 1152 宽窗口） | 圆角 |
| --- | --- | --- |
| 木牌、铭牌、按钮、标签、仪表外圈 | 3 px / 2 px 可可墨 | 按物体：按钮是胶囊形（高度的一半）；标签 12；铭牌 18；路牌四角略不同（12/16/12/14），带手绘感 |
| 屏幕外框、样张外框 | 3 px | 14 |
| 图表坐标轴 | 2 px | — |
| 图表网格 | 1 px，`#D7ECF7`（就是笔记纸的方格） | — |

- **取消 v1.1 的“只有按钮用圆角”。**游戏里没有直角的东西，所以界面里也不用直角。
- **取消细灰分隔线。**区块之间用木牌、铭牌这些“物体”分开，不再用 1 px 灰线。
- **“厚度”代替阴影：**按钮、路牌和成就提示下面有一条 3–5 px 的实心下沿（可可墨或木牌边色），像贴纸贴在木板上。不用模糊阴影，也不用渐变。
- 木牌可以有 ±1.5° 的倾斜（应用名挂牌、路牌、封面图、评级章）。读数、仪表和图表**不倾斜**。

### 3.3 字体

| 角色 | 字体 | 用在 | 不用在 |
| --- | --- | --- | --- |
| 标题字 | **站酷快乐体 ZCOOL KuaiLe**（OFL，Google Fonts） | 应用名、页面大标题、路牌上的游戏名、铭牌名（方向 / 力 / 力矩）、成就名、评级章 | 20 号以下的字、正文、按钮、读数、数字 |
| 正文和读数 | **Atkinson Hyperlegible Next**（数字、拉丁字母）+ **Noto Sans SC**（中文），沿用 v1.1 | 正文、按钮、标签、所有读数和分数 | — |

- 站酷快乐体是圆头手写体，和游戏里圆润的描边风格一致。它只有一个字重，所以只用作标题，不加粗。
- 读数仍用 Atkinson：易读是硬要求，可爱不能以看错数字为代价。
- 英文界面的标题字体：站酷快乐体的拉丁字母也是同样的手写风格，可以直接用。如果觉得英文太花，可以换成 **Fredoka**（OFL）。
- 字号阶梯沿用 1.25 倍：13 / 16 / 20 / 25 / 31 / 39 / 49。v2.0 新增 39，用于详情木牌上的游戏名和报告标题。

| 用途 | 字号 | 字体 |
| --- | ---: | --- |
| 实时读数 | 49 | Atkinson Bold |
| 详情木牌上的游戏名 | 39 | 站酷快乐体 |
| 应用名挂牌、评估报告标题、总分 | 31 | 站酷快乐体（总分用 Atkinson Bold） |
| 路牌上的游戏名、铭牌名 | 25 | 站酷快乐体 |
| 成就名、主按钮 | 20 | 站酷快乐体 / Atkinson Bold |
| 正文、按钮、标签 | 16 | Atkinson / Noto Sans SC |
| 说明、目标范围、图例 | 13 | Atkinson / Noto Sans SC |

### 3.4 动效

| 动效 | 何时出现 | 时长 |
| --- | --- | --- |
| 按钮按下：沉下 3 px，下沿变薄 | 按下时（回应操作） | 80 ms |
| 选中路牌：向右拉出 10 px | 选中时（回应操作） | 120 ms |
| 目标区由嫩叶色逐渐变成叶绿 | 保持期间（沿用 v1.1，状态反馈） | 随保持时间 |
| 成就提示木牌从上方吊下，轻晃一次后停住 | 解锁成就时（这是一个事件，不是装饰） | 约 400 ms |

**不做：**进场动画、悬停放大、背景云朵在菜单里飘动。游戏画面里的云照常飘。

- 保留 v1.1 的“左边列表、右边详情”和从上到下“游戏 → 关卡 → 难度 → 开始”的顺序。
- 路牌：木牌色。选中的路牌变白，描边加粗，向右拉出，下沿换成胡萝卜橙，左侧有一颗橙色钉子。尚未推出的游戏用暗一些的木色和干土色文字。**不用半透明**，否则背后的栅栏会透出来，显得脏。

### 4.2 入门测试

- 一块大木牌上钉三块并排的奶油色铭牌，取代 v1.1 的竖线三栏。
- 铭牌内从上到下依次是：名字（站酷快乐体 25）、仪表、读数（49）、目标范围（13）、保持进度条和状态文字。
- 仪表：白色表面，3 px 可可墨外圈；刻度用干土色；目标区未进入时是嫩叶色，保持时逐渐加深到叶绿；指针是可可墨杆、胡萝卜橙头，中心钉也是橙色。
- 状态不只靠颜色：“已解锁 ✓”、“保持中”、“未解锁”文字始终显示（沿用 v1.1 的色盲规则）。
- 键盘提示写在土上，白字加可可墨描边，和游戏里的写法一样。

### 4.3 评估报告

- 一张方格笔记纸用金属夹子夹在木牌上。方格（24 px）同时就是图表的网格，所以图表内部不再另画网格。
- 图表：白底、可可墨坐标轴。本局曲线是可可墨实线（3 px），标准曲线是深天蓝虚线，上限线是番茄红虚线；爆掉 / 用力过猛是番茄红圆点，漏气是番茄红空心圈，绑好 / 保持成功是叶绿竖线。
- 评级是一枚斜 8° 的双圈圆章，字用站酷快乐体：S/A/B/C/D 用叶绿，F 用番茄红。
- 分项：名称、权重、分数，下面是胶囊形分数条（干土色，**不用状态色**，因为分数高低不是“状态”），再下面一行是具体数字。
- “保存到文件夹”是橙色主按钮，“关闭”是奶油纸按钮，放在纸外右上角。截图保存时隐藏这两个按钮（沿用现有做法）。
- 报告图片导出后会被打印或发给老师，所以纸面和图表必须保持高对比度。木牌只在纸的外圈露出来。

### 4.4 成就页和历史记录

- 成就页：每个成就是一块小铭牌（奶油纸、可可墨描边），图标放在左边的方框里。已解锁的铭牌下沿是叶绿色；未解锁的图标保持现在的灰色处理，铭牌为暗木色。筛选用标签样式。
- 历史记录：一张大的笔记纸（同报告），每局一行，行之间用方格线分隔。“查看报告”是奶油纸小按钮，评级用小号评级章。

### 4.5 游戏内

游戏画面本来就是这套风格的来源，不用改。只统一以下几处：

- 结算面板里的按钮改用本方案的按钮样式（现在是 18 px 圆角矩形加 3 px 描边，改为胶囊加下沿）；
- 游戏里的提示文字（如“太快了！慢一点”）沿用现在的可可色字加白色描边。

## 5. 原则

1. **同一片菜园：**菜单、测试、报告和游戏是同一个地方，背景、描边和木牌都一致。
2. **木牌和描边是唯一的大胆之处：**其余部分安静、整齐，文字和数字不加装饰。
3. **读数永远最清楚：**读数用 Atkinson 49 号，不倾斜，放在纯色底上。
4. **颜色分工明确：**场景色可以铺满；橙色表示“去按它”；绿、黄、红只表示状态。
5. **用厚度表示可以按：**有下沿的东西可以按，没有下沿的东西只是展示。
6. **动效只回应操作和事件。**
7. **中英文同一版式**（沿用 v1.1）。
8. **色盲可读：**状态始终有文字或形状（✓、×、空心圈）陪着颜色。

## 6. 对照需求自查：哪些地方没有用默认做法

| 最初的想法 | 为什么放弃 | 改成 |
| --- | --- | --- |
| 只把 v1.1 的颜色换成游戏里的橙和绿 | 用户明确要求不只换配色；而且换色后，细灰线加直角的“仪器”外形和游戏仍然不搭 | 形状、描边、字体、背景、动效一起改，界面元素都变成菜园里的物体 |
| 白色圆角卡片加柔和投影 | 通用 App 模板，游戏里没有这种东西 | 有厚度、插在土里的木牌；用实心下沿代替模糊投影 |
| 全部换成可爱的手写体 | 读数和报告要求一眼看清，手写体的数字容易看错 | 手写体只用于 20 号以上的标题，正文和数字保留 Atkinson |
| 菜单背景放会动的云和兔子 | 抢读数和按钮的注意力；兔子是游戏的角色，在菜单里出现会喧宾夺主 | 背景只放天空、栅栏和泥土，静止不动 |
| 报告也做成木牌 | 报告要打印或发给老师，木纹底会降低图表的清晰度 | 报告是夹在木牌上的白色方格纸，木牌只作外框 |
| 每个按钮都用橙色 | 颜色失去含义，看不出该按哪个 | 一页只有一个橙色主按钮 |

## 7. 实施说明（Godot，确认后再做）

- **木牌：**`NinePatchRect`，纹理用 `assets/carrot_game/ui_result_panel.png`，四边边距约 70 px（按 1920 宽）。木桩用 `ColorRect` 或 `_draw()` 画，放在木牌后面。
- **按钮、标签、铭牌：**`StyleBoxFlat`，`border_width_all = 2`，`border_color` 设为可可墨；下沿用 `shadow_size = 0`、`shadow_offset = (0, 4)`、`shadow_color` 设为可可墨，可以做出实心下沿。按下状态改 `shadow_offset = (0, 1)`，`content_margin_top` 加 3。
- **背景：**菜单页底层放一个 `TextureRect` 组合，依次是天空、栅栏、后土、前土四张图（和游戏同一套），`STRETCH_KEEP_ASPECT_COVERED`。
- **字体：**新增 `fonts/ZCOOLKuaiLe-Regular.ttf`（约 2–5 MB，OFL），放在 `fonts/` 并附许可文本。正文字体不变。
- **令牌：**新建 `views/palette_v2.gd`（或新版本里的 `palette.gd`），旧的 `palette.gd` 不动。`ui_kit.gd` 的 `button()`、`toggle()`、`box()` 改成按新令牌生成样式，各页面视图不用逐个改颜色。
- **范围：**改动只在 `views/`，模型和主持者不动，这也是 v0.5.4 做 MVP 分层的好处。
- **建议的版本号：**v0.7.0（新界面风格）。按惯例新建 `app_v0.7.0/`，旧版本保留。
